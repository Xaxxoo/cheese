Section 03

Off-Ramp Flow

The off-ramp flow converts a user's USDC balance on Stellar into local currency deposited to their bank account via Bridge. This enables withdrawals in KES, GHS, RWF, and ETB.

USDC → Local Bank Payout via Bridge
1

User Initiates Withdrawal

User selects destination country and enters amount in local currency. Frontend calls POST /banks/transfer with country code and bank details.

2

Rate Quote & Confirmation

BridgeService fetches a live FX quote from Bridge for the requested currency pair (USDC → local). The quoted rate and fees are displayed to the user for confirmation.

3

USDC Locked & Transfer Created

BridgeService debits the user's USDC balance (internal ledger hold), creates a BridgeTransfer record with status pending, and a parent Transaction record.

4

Bridge API Call — Create Transfer

BridgeClient sends POST /v0/transfers to Bridge with source (USDC on Stellar), destination (local bank), amount, and beneficiary details. Bridge returns a transfer_id.

5

USDC Settlement to Bridge

Backend sends the USDC from the CheesePay Stellar treasury account to Bridge's designated Stellar address. The Stellar transaction hash is recorded on the BridgeTransfer.

6

Bridge Executes Local Payout

Bridge converts USDC to local currency at the locked rate and initiates the bank transfer through its local banking partner network.

7

Webhook Confirmation

Bridge sends a webhook (transfer.completed) to POST /webhooks/bridge. The handler updates the BridgeTransfer and parent Transaction to completed. User receives a push notification.

Failure Handling

  • If Bridge API returns an error at step 4, USDC hold is released and the Transaction is marked failed
  • If the Stellar payment fails at step 5, the BridgeTransfer is cancelled via DELETE /v0/transfers/:id
  • If Bridge webhook reports transfer.failed, USDC is refunded to the user's balance and a failure notification is sent
  • Idempotency keys prevent duplicate transfers on network retries
Section 04

On-Ramp Flow

The on-ramp flow allows users to deposit local currency and receive USDC credited to their Stellar wallet. Bridge handles the local currency collection and USDC settlement.

Local Currency → USDC via Bridge
1

User Requests Deposit

User selects "Add Money" and chooses their local currency (KES, GHS, RWF, or ETB). Frontend calls POST /wallet/deposit/bridge with the amount in local currency.

2

Bridge Payment Link Created

BridgeClient calls POST /v0/transfers with source as local currency and destination as USDC on Stellar. Bridge returns payment instructions (bank details or mobile money info) for the user to complete.

3

User Completes Local Payment

User transfers local currency to the provided bank or mobile money details. This happens outside the CheesePay app via the user's local banking app or mobile money wallet.

4

Bridge Detects Payment

Bridge confirms receipt of local currency funds through its banking partners. Webhook transfer.payment_received is sent to CheesePay. BridgeTransfer status updates to processing.

5

USDC Settled to CheesePay

Bridge converts the local currency to USDC and sends it to the CheesePay Stellar treasury address. The Stellar transaction is detected by the backend's deposit monitor.

6

USDC Credited to User

Backend credits the USDC to the user's internal balance, creates a deposit Transaction record, and sends a push notification confirming the deposit.

Section 05

Country Coverage & Routing

Bridge serves as the unified payment rail for all four target markets. The BridgeService uses the user's country code to determine the correct currency and available payment methods for each transaction.

// bridge.service.ts — country configuration const SUPPORTED_COUNTRIES = { 'KE': { currency: 'KES', methods: ['mpesa', 'bank_transfer'] }, 'GH': { currency: 'GHS', methods: ['mobile_money', 'bank_transfer'] }, 'RW': { currency: 'RWF', methods: ['mobile_money', 'bank_transfer'] }, 'ET': { currency: 'ETB', methods: ['bank_transfer'] }, }; function createTransfer(countryCode: string, amount: number) { const config = SUPPORTED_COUNTRIES[countryCode]; if (!config) throw new UnsupportedCountryError(countryCode); return this.bridgeClient.createTransfer({ source_currency: 'usdc', destination_currency: config.currency, destination_payment_rail: config.methods[0], amount, }); }

Rate Handling

  • Bridge provides and locks the FX rate at transfer creation time — CheesePay displays the Bridge-quoted rate to the user before confirmation
  • Rates are cached in Redis with a 60-second TTL to minimize API calls while keeping quotes fresh
  • The locked rate is stored on the BridgeTransfer entity for audit and reconciliation
  • Users see the exact amount they will receive in local currency before confirming the transaction

Idempotency & Reliability

  • Webhook deduplication: Each webhook is stored with its event_id — duplicate deliveries are detected and skipped
  • Transfer idempotency: Each transfer request includes a client-generated idempotency key tied to the Transaction UUID
  • Retry logic: BullMQ jobs retry up to 3 times with exponential backoff (1s, 4s, 16s) on transient failures
  • Reconciliation cron: A scheduled job polls GET /v0/transfers/:id for any transfers stuck in processing for >30 minutes

Security Architecture

  • Device signatures: HMAC-SHA256 device binding prevents credential replay from unknown devices
  • PIN protection: Client-side HMAC hashing with userId salt, server-side bcrypt — PIN never transmitted in plaintext
  • Wallet encryption: Stellar secret keys encrypted at rest with AES-256 using a per-deployment encryption key
  • Webhook verification: All inbound Bridge webhooks validated via HMAC signature before processing
  • Rate limiting: NestJS Throttler guards on auth and transaction endpoints
  • Tiered access: KYC tier determines transaction and withdrawal limits (Silver → Gold → Black)
